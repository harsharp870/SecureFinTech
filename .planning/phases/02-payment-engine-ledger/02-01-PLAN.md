# Plan 02-01: Wallet & Transaction Database Schemas and Service Logic

**Phase:** 02 - Payment Engine & Ledger
**Plan:** 01 of 02
**Requirements:** PAYM-01, PAYM-02, PAYM-03

## Objective
Create SQLAlchemy database models for `Wallet` and `Transaction`, double-entry ledger structures, `FraudEvaluator` hook interface, and atomic transfer service logic with deterministic pessimistic row-locking (`SELECT FOR UPDATE`). Wire automatic `$10,000 USD` wallet creation into the user registration workflow.

## Proposed Changes

### Database Models & Schemas
- Create `backend/app/models/payment.py`:
  - `Wallet` model: `id`, `user_id` (FK to `users.id`), `balance` (`Numeric(12,2)` default `10000.00`), `currency` (`default="USD"`), `created_at`, `updated_at`.
  - `TransactionStatus` enum: `PENDING`, `APPROVED`, `FLAGGED`, `BLOCKED`, `FAILED`.
  - `Transaction` model: `id`, `reference_id` (UUID), `sender_id` (FK), `recipient_id` (FK), `amount` (`Numeric(12,2)`), `currency`, `status`, `risk_score`, `risk_level`, `failure_reason`, `note`, `created_at`, `updated_at`.
- Export new models in `backend/app/models/__init__.py`.
- Create Pydantic schemas in `backend/app/schemas/payment.py`:
  - `WalletResponse`, `DepositRequest`
  - `TransferRequest`, `TransactionResponse`, `TransactionDetailResponse`, `TransactionHistoryParams`

### Fraud Evaluator Hook Interface
- Create `backend/app/services/fraud_evaluator.py`:
  - Define `BaseFraudEvaluator` abstract class and `FraudEvaluationResult` schema.
  - Implement `Phase2PassThroughEvaluator` that mock auto-approves transactions (ready for Phase 3 ML integration).

### Payment Service Logic
- Create `backend/app/services/payment.py`:
  - `get_or_create_wallet(db, user_id)`: Initializes wallet with $10,000 balance if not present.
  - `deposit_funds(db, user_id, amount)`: Increments balance in atomic transaction.
  - `execute_p2p_transfer(db, sender_id, recipient_id, amount, note)`: Performs deterministic locked P2P transfer with `SELECT FOR UPDATE` (ordered by wallet ID), evaluates via `FraudEvaluator`, and commits balance mutation iff approved.

### Registration Hook Update
- Modify `backend/app/services/auth.py` or user creation logic to automatically call `get_or_create_wallet` when a new user registers (`AUTH-01` alignment).

## Verification Plan

### Automated Tests
- Run `pytest backend/tests/test_payment_service.py` verifying:
  - Auto-creation of $10,000 wallet on user signup.
  - Deposit service increasing wallet balance.
  - Atomic transfer debiting sender and crediting recipient.
  - Rejection of insufficient balance, self-transfers, and non-existent users.
