# Plan 02-02: Payment API Endpoints & History Filtering

**Phase:** 02 - Payment Engine & Ledger
**Plan:** 02 of 02
**Requirements:** PAYM-01, PAYM-02, PAYM-03, PAYM-04

## Objective
Implement FastAPI routers for wallet operations and payment transfers, history query filtering with limit/offset pagination, and single transaction detail lookup. Register routes in `backend/app/main.py`.

## Proposed Changes

### Wallet Endpoints (`backend/app/api/v1/wallet.py`)
- `GET /api/v1/wallet/me`: Returns current user's wallet balance and currency.
- `POST /api/v1/wallet/deposit`: Endpoint allowing user to deposit simulation funds.

### Payment Endpoints (`backend/app/api/v1/payments.py`)
- `POST /api/v1/payments/transfer`: P2P transfer endpoint taking `recipient_email` or `recipient_id`, `amount`, and optional `note`. Calls `execute_p2p_transfer` service.
- `GET /api/v1/payments/history`: Returns paginated transactions (`page`, `size`) for authenticated user with optional filters (`direction`: `sent` | `received` | `all`, `status`, `start_date`, `end_date`).
- `GET /api/v1/payments/{transaction_id}`: Returns full details for a specific transaction ID if the authenticated user is either sender or recipient (or admin). Returns `404 Not Found` or `403 Forbidden` otherwise.

### App Router Registration
- Include `wallet.router` and `payments.router` in `backend/app/main.py` under `/api/v1`.
