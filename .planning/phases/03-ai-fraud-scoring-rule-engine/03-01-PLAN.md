# Plan 03-01: Deterministic Security Rules Engine & Feature Extractor

**Phase:** 03 - AI Fraud Scoring & Rule Engine
**Plan:** 01 of 02
**Requirements:** FRAD-01, FRAD-02, FRAD-03

## Objective
Implement transaction feature extractor and deterministic security rules engine evaluating transfer amount thresholds, high velocity windows, rapid succession timing, and account drain ratios.

## Proposed Changes

### Feature Extractor Service (`backend/app/services/fraud_engine/feature_extractor.py`)
- Extract feature vector `[amount, velocity_5m, seconds_since_last_tx, balance_ratio, hour_of_day]` from DB context:
  - `amount`: float
  - `velocity_5m`: count of transactions by sender in last 300 seconds
  - `seconds_since_last_tx`: elapsed time since sender's most recent transaction (default 86400.0 if first tx)
  - `balance_ratio`: transfer amount divided by sender's wallet balance
  - `hour_of_day`: UTC hour (0-23)

### Deterministic Rules Engine (`backend/app/services/fraud_engine/rules_engine.py`)
- Implement `BaseRule` class and concrete rule classes:
  - `HighAmountRule`: >= $5,000 (+40 pts); >= $10,000 (+85 pts, critical override).
  - `HighVelocityRule`: > 3 transactions in 5 minutes (+35 pts).
  - `RapidSuccessionRule`: < 30 seconds since previous transaction (+30 pts).
  - `AccountDrainRule`: transfer amount > 90% of sender's wallet balance (+25 pts).
- Implement `evaluate_rules(db, sender_id, amount, sender_wallet_balance) -> Tuple[float, List[RuleResult], bool]` returning aggregated rules score, list of triggered rule results, and critical override boolean flag.

## Verification Plan

### Automated Tests
- Create `backend/tests/test_rules_engine.py` testing:
  - High amount rule triggering for $5k and $10k transfers.
  - High velocity rule triggering when 4 transfers occur in 5 minutes.
  - Rapid succession rule triggering for transfers 15 seconds apart.
  - Account drain rule triggering when transferring $9,500 out of $10,000 balance.
